# contract-tester (Contract Test Generation)

> **Core Concept**: "Automated generation and execution of contract tests based on Zod schemas"

Analyzes Zod schemas produced by contract-codegen to generate comprehensive contract tests automatically. Generates 6 categories of tests: valid request acceptance, missing required field rejection, type constraint boundary values, error code exhaustiveness, error response common schema compliance, and API metadata verification.

## Core Principles

1. **Schema-Driven Testing**: Test cases are automatically derived from the structure of Zod schemas.
2. **Guaranteed Exhaustiveness**: Covers all aspects of the contract across 6 test categories.
3. **TDD Support**: Supports the Test Generation → Red → Implementation → Green cycle.

---

## Key Features

### 1. Valid Request Acceptance Tests

**Description**: Validates that well-formed requests pass schema validation.

```typescript
describe('Valid request acceptance', () => {
  it('passes validation when all required fields are set correctly', () => {
    const validRequest = { /* automatically generated from Zod schema */ };
    expect(() => RequestSchema.parse(validRequest)).not.toThrow();
  });
});
```

### 2. Missing Required Field Rejection Tests

**Description**: Validates that validation errors occur when required fields are missing.

```typescript
describe('Missing required field rejection', () => {
  it.each(requiredFields)('throws ZodError when %s is missing', (field) => {
    const invalidRequest = { ...validRequest };
    delete invalidRequest[field];
    expect(() => RequestSchema.parse(invalidRequest)).toThrow(ZodError);
  });
});
```

### 3. Type Constraint Boundary Value Tests

**Description**: Validates schema boundary behaviors on constraints such as min/max/pattern.

```typescript
describe('Type constraint boundary values', () => {
  it('rejects string with minLength - 1', () => { /* ... */ });
  it('accepts string with minLength', () => { /* ... */ });
  it('accepts string with maxLength', () => { /* ... */ });
  it('rejects string with maxLength + 1', () => { /* ... */ });
});
```

### 4. Error Code Exhaustiveness Tests

**Description**: Validates that responses for all error codes defined in the SPEC conform to the correct schema.

### 5. Error Response Common Schema Compliance Tests

**Description**: Validates that all error responses comply with the common error schema (error code, message, details).

### 6. API Metadata Verification Tests

**Description**: Validates that endpoint metadata such as method, path, and Content-Type match the SPEC.

## Execution Flow

```
Pre-flight Checklist output + verification
        | (all [x])
Phase 1: Schema Analysis (sonnet)
  - Read Zod schemas from contracts/schemas/
  - Analyze schema structure to enumerate test case candidates
        |
Phase 2: Test Generation (sonnet)
  - Generate test files based on 6 test categories
  - Output to tests/contract/{feature}.contract.test.ts
        |
Phase 3: Test Execution (sonnet)
  - Run generated tests with project-config.json#commands.test (contract tests, dynamically detected if null)
  - Analyze results to determine PASS/FAIL
        |
Post-flight Checklist output + verification
        | (all [x])
Completion Report + Evidence Cache
```
