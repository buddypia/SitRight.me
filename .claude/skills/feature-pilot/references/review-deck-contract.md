# Review Deck Content Contract

What feature-pilot review decks contain and how the narrative is authored. Loaded from `SKILL.md` § Stage Review Checkpoints when generating or writing a deck.

- **Original Request + Semantic Categorization**: Top of deck displays **verbatim original user request** (PLAN.md `## Original Request` priority 1 / session passport priority 2) alongside **AI interpretation** to enable 3-way reconciliation: request ↔ interpretation ↔ result (Google Review Step 1 = "Is the change sound? Is explanation clear?"). Below that, **Where to Look First** includes **machine-detected risk signal chips + missing explanation chips only** (scale badges, metric tiles, headline sentences, review budget removed per user feedback). Files are grouped in **global → modular → local + diff size order**, with tests tagged "Recommended reading first". Decision items comprise `Question + PASS Criteria + Evidence Anchor + Risk Level`, displaying **only axes relevant to the current change** (0 new files → exclude Design, 0 executable code changes → exclude Complexity, 0 contract surface changes → exclude Documentation). SSOT `lib/change-taxonomy.mjs` · `lib/review-origin.mjs`.
- **Impact Map**: Decks with changeset diffs (CP-MILESTONE / CP-SHIP) automatically include a `What Changed · Why · Impact` section: ① **Area × Change Nature Matrix** (Vertical = registered features ∪ path areas, Horizontal = impl/test/config&data/docs, Density = file count), ② **Where to Look First** top 6 + rationale for order, ③ **What·Why·Impact 3-column ledger** (Why = quote `file_notes[].reason`, Impact = contract surface / companion tests / deletions), ④ **8 Contract Surfaces** (rules, hooks, deploy registry, schema, pipeline, skills, command entrypoints, dependencies) — **unmodified surfaces are explicitly marked "Unchanged"**. Feature mapping cross-checks `docs/features` ownership index mechanically, placing declared `affected_features` side-by-side to warn on declared-only / machine-only discrepancies. SSOT `lib/deck-impact.mjs`.
- **Full Verbatim Sections**: Deck includes **all sections** of SPEC.md / PLAN.md / wireframes (tables as tables, code as code — `lib/doc-outline.mjs` → `lib/doc-section-render.mjs`). Implementation contract sections are grouped toward the top, preceded by original table of contents (section length and status). Incomplete sections are tagged with badges — `No Content` / `Unwritten (TBD)` / `Single Line (N chars)` — serving as risk chips.
- **Visuals**: Stage decks start with **Where to Look First** (risk chips with anchor jump + missing item chips); the ship deck starts with the brief (CP-SHIP contract below) and shows the same chips right after it. Only **2 stage diagrams** remain: CP-SPEC **Requirements Readiness Grid** (FR × Korean requirement, why, how, acceptance criteria fulfillment) and CP-SHIP **Requirements → Implementation File Linkage Map** (unlinked items warn of coverage holes). Treemaps removed. `--diagram <svg>` is an additional optional channel.
  - **No Decorative Elements**: Single-number donuts, step-name flow diagrams, repetitive labels, and instruction boilerplate are removed. When adding visuals, ask: "Does this diagram provide more actionable judgment information than a table or list?" If NO, do not include.
- **Evaluation Item Risk Levels**: Checklist items have `severity` (critical / major / info), sorted by risk level with a 12-item ceiling applied **after sorting**. User-provided `--checklist-json` follows the same sorting and truncation.
- **Mandatory AI Narrative**: Gate decks require `--narrative-json` — numbers and filenames alone do not constitute review material. AI writes in context: `what/why/how/next` (story) + milestone `file_notes[]` (what changed per file and why) + spec `fr_notes[]` (FR requirement `ko` + `why` + `how`). Calling CLI without narrative fails. Machine generation applies to **evidence** only; narrative layers are authored by AI and marked "AI Authored".
- **Mandatory Review Depth Fields**: Narrative must include: `tradeoffs[]` (`{topic, chosen, rejected, why, cost}` — `cost` = what the chosen option gives up; at ship, `topic: "Single approach"` is **rejected**: name the alternative you would have taken and why not), `affected_features[]`, and where applicable `api_changes[]` (`{surface, before, after, compat}`) and `spec_changes[]` (`{doc, change}`). `impact` and `regression_risk` are stage-deck fields; at ship they are optional and superseded by `failure_modes[]` / `exposure` (below) — when written they render under folded evidence. Stage decks render `cost` when present and show missing-channel chips for the other fields; ship decks fail generation on any missing field (`lib/narrative-quality.mjs`).
- **CP-SHIP Impact-First Brief Contract**: The first screen of the ship deck opens with **how far the change reaches**, computed from git paths by `lib/change-reach.mjs` against the project map `.claude/reach-map.json` (project-owned, never transplanted; without it builtin conventions apply and the deck says so) — four tiers, highest first: `data` (stored data / contracts other systems read: schemas, process contracts, infra) → `product` (what users or generated projects receive) → `pipeline` (build / gate / ship scripts, hooks, CI, manifests) → `local` (docs, tests, plans). Run `node .claude/scripts/ship-deck.mjs --reach --worktree <path>` **before** writing the narrative: it prints the tier and what the gate will demand. Then the brief: what · for whom · why · how → `exposure` (`{who, how_many, when, reversible}`, **required at product/data**) → `data_change` (`{what_moves, count, irreversible, order, consumers}`, **required at data**) → `failure_modes[]` (`{scenario, who_notices, detect, mitigation}`, ≥1 always, **≥2 at product/data**) → optional `diagram` (`{kind: flow, steps:[{label, note, state: same|changed|new|removed}]}` or `{kind: before_after, rows:[{aspect, before, after}]}` — the renderer draws it) → chosen vs rejected **with cost** → `review_focus[]` (`{where, check, risk_if_wrong}`, 1–4) → `known_gaps[]` (≥1) · `out_of_scope[]` · `rollback`. **No file list in the first view.** `requirements[]` and `file_notes[]` are optional at ship; when written they must match the changeset and render under folded evidence. Start from the skeleton: `node .claude/scripts/ship-deck.mjs --template`. Word-level gate (`lib/narrative-quality.mjs`, fail-closed, no glossary dependency, word lists keyed by locale — en, ko): per-field character ceilings (rejected, never truncated), hype words (perfect·seamless·완벽·0ms…), empty activity phrases (ensure traceability·추적성 확보…), session-local locators (Section 8e.5, DEBT-n, R-CM-n) in brief prose, performance numbers without a measurement note, placeholders (none·n/a·tbd·없음) in self-critique fields. Mismatches with git diff fail generation. The gate runs only when the deck is generated — i.e. for large ships (R-CM-030 Rule 12). `review_decisions[]` deprecated — ship verdict via chat 3-choice channel.
  - **Authoring protocol — argue against yourself before writing** (the gate checks words; only you can check thought): ① say the change in one sentence to someone who was not there; ② list the alternatives you *actually* weighed and what the chosen one costs — if you cannot name a cost, you did not compare; ③ ask "where would a skeptical reviewer look first, and what breaks for whom if it is wrong?" — that is `review_focus`; ④ write what you did **not** do and what you did not verify — that is `known_gaps`; ⑤ delete every adjective that asserts quality and every identifier that only you understand. Describe behavior, not internals.
- **Plain Language Contract**: Narrative prose targets **general software engineers** — universal developer vocabulary (hook, revert, regression, scaffold) needs no explanation; **brief2dev-specific terms must be defined**. Latin/specialized terms must be registered in glossary (`data/registry/glossary.json` SSOT), inlined in narrative `glossary[]` (`{term, plain}`), or annotated inline as "term (explanation)" or deck CLI rejects generation (SSOT `.claude/scripts/lib/plain-language.mjs`).
