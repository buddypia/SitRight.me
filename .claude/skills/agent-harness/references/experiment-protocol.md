# 比較実験と反証の記録

対象: harness・モデル・tool routing・姿勢判定パラメータなどの改善を測定して採用する作業。出典はローカル資料 `hanakoxbt_article/post.md`。単純な誤字修正には使わない。

1. **履歴を読む。** `docs/harness/INDEX.md` と同領域の経験、PLAN の Decisions を開く。却下済みの案は入力・実装・制約が変わった理由なしにやり直さない。
2. **測る前に契約を書く。** PLAN に仮説・baseline commit・候補・固定入力・全ケース・合否・最大試行数を書く。既存の最大 5 QA / 同一エラー 3 回の上限を広げない。時間・費用予算は依頼にある場合に記録する。
3. **入力を確かめる。** 出典・作成方法・範囲・欠損、synthetic / 実測を記録する。合成 landmark は契約の検証用で、実ユーザーの精度の証明にはならない。姿勢データは同意・保管規則に従い、映像を外部送信しない。
4. **調整用と独立検証用を分ける。** 同じ fixture だけで調整と精度主張をしない。時系列では過去で調整し後続期間を評価する。姿勢の実測なら人物・撮影セッション単位で分ける。利用できなければ `未検証` と書き、実データを作ったことにしない。
5. **全ケースを実行する。** baseline と候補を同じ入力で比較する。閾値・timeout・routing は近傍値と境界も含め、失敗・同点・欠損も残す。一番良いセルだけで採用しない。時間を測る場合は warm/cold、端末と負荷も記録する。
6. **反証する。** 独立 reviewer に要件・入力・diff・実行結果を渡す。最悪ケース、欠損、近傍条件、別セッション、キャッシュからの再開で壊せるかを確認させる。既存レビュー経路を使い、役職ごとの常設 subagent を増やさない。試したことと読むだけの確認を分ける。
7. **記録してから要約する。** 下の記録を PLAN に残し、持ち越せる観察だけ既存の経験ライブラリへ移す。影響を切り分けられなければ `切り分け不能` とする。

```markdown
### E-<番号>: <問い>
- 状態: open | accepted | rejected
- baseline / candidate: <commit または patch>
- 入力: <出典、範囲、欠損、synthetic/実測>
- 調整用 / 独立検証用: <区切り、未提供なら未検証>
- 採用条件: <事前の期待、退行してはいけない条件>
- ケース / 結果: <失敗を含む全ケースと証拠への参照>
- 反証: <reviewer、試した入力、最弱点、未検証範囲>
- 判定: VALIDATED | TRADE_OFF | NO_BENEFIT | UNVERIFIED
- 次: <採用 / 修正 / KEEP_BASE、再試行に必要な新しい根拠>
```

`VALIDATED` は宣言した範囲で条件を満たし、反証で重大な欠陥が出なかったこと。`TRADE_OFF` は改善と退行があるため既存承認ポリシーで判断する。`NO_BENEFIT` は KEEP_BASE の根拠。証拠不足は `UNVERIFIED`。機能全体の完成や実環境の精度を、この判定だけで宣言しない。

小さい再現入力から既存の全体 gate、必要な CI / 実環境確認へ進む。実験と本番変更・デプロイ権限は既存 worktree / ship 経路で分離する。追加 MCP・有料サービス・固定モデル名は前提ではない。
