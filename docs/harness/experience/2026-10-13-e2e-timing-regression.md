# e2e の失敗を再実行で流さず、CI ログの時刻を main と比べて性能の退行を探す

- 領域: e2e
- 日付: 2026-10-13
- 出典: #40, #42（7bb7669）, #44（60f6416）, #62（3c78e2b）

## 部品ごとの変更と観察

| 部品 | 変更 | 観察 | 判定 |
|---|---|---|---|
| CI ログの時刻の比べ方 | #40 のあとの e2e 失敗を、不安定なテストとして再実行せずに時刻で比べた（#42） | alert 105s → 120-128s、offline のテスト 1.8m → 2.5m の遅れが見つかり、全面オーバーレイの `backdrop-blur` が推論ループを止めていたと特定できた。5 回中 1 回は通っていたので、再実行で通せば見逃していた | 効いた |
| `AGENTS.md`（常駐、当時は `CLAUDE.md`） | 「e2e が一度でも落ちた PR は、原因を特定するまでマージしない」を足した（#42）。#44 で比べる時刻に `avatar ready at` を加えた | 以後、#62 では消えるのが早い回復トーストの見逃し（SwiftShader でスクリーンショットに 10 秒前後かかる）を突き止めてテストを直し、再実行で流さなかった。規則なしの実行と比べていないので、規則が効いたかは言えない | 切り分け不能 |

## 持ち越す教訓

- **きっかけ**: 描画やメインスレッドの負荷に触れる変更のあとで、e2e がときどき落ち、再実行すると通る
- **教訓**: 再実行で通す前に、CI ログに出している時刻（`calibrated at` / `alert at` / `avatar ready at`）とテストの所要時間を main の直近の成功 run と比べる。遅れていれば性能の退行として原因を探す。比べたい時点がログに無ければ、まず e2e に時刻のログを足す（`AGENTS.md` の規則と `tests/e2e/` のログ）
- **根拠**: 調べ方の行は #42 で退行を特定した（効いた）。規則を常駐させた行は「切り分け不能」
- **確度**: 中 — 時刻の比較が原因の特定に効いたのは 1 件。規則そのものの効果は未確認
